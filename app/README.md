# Halbach Hall workstation (app/)

Double-click `start-workstation.bat` on the measurement PC. It serves the UI from the local Rust service and connects the browser automatically, without a token prompt. Live Server on allowed loopback origins also connects automatically. GitHub Pages, other remote origins, direct file access and computers without the local service provide project inspection and data analysis only. See [Rust backend setup](../rust-backend/README.md).

The light workstation interface opens with plain method selection rows: DC field, AC field, CHIRP and **Load preset**. Load preset opens a JSON file picker. On Devices, **Save method & devices as JSON** exports the current method and all device settings in the same preset format, excluding sample data and measurements. Loading replaces method/device settings, preserves sample/data, and invalidates connection checks. Examples are in `presets/`: `dc-delta.json`, `ac-dc.json`, and `chirp.json`; edit addresses for your bench. Numerical controls, including TTL timeout, now appear in Experiment setup.

Method defines only the measurement principle: field mode, DC or AC current, and steps or scans. Delta is selected on Devices as source-linked DC voltage acquisition and automatically reverses polarity. AC-field/DC-current measurements acquire each signed current and fit voltage against current with a free intercept. The Data inspect page shows that line. CHIRP specifies cycles per current level and direction, with dwell = cycles / maximum rotation frequency; the universal rotation limit is 1.2 Hz. The guide's slower commissioning speeds remain useful for filter tracking validation.

After successful connection checks, Method and Devices become read only. Use **Stop setup and edit configuration** before starting, or Pause/Abort in Run, to release them. Changing the method principle or devices invalidates the check. Parameter edits in Experiment setup preserve it. During a program, **Apply conditions & program** validates and queues the settings for the next measurement. Active measurements retain their original settings; each saved run includes its method and device snapshot. Active thermal targets, ramp rates, repeat counts and waits can be edited. Future steps can be added, removed, reordered or replaced while running. Completed steps and the active operation type remain fixed. Real Pause disables outputs and motion, retains partial data and releases hardware sessions; Resume restarts an interrupted acquisition and retains the completed measurement count, rechecks identities and restores temperature stability when needed. Device changes require fresh connection checks before Resume.

Workflow: Method → Devices → Sample → Experiment setup → Run → Data inspect → Analysis. Select DC field (steps/scans, DC or AC current), AC field (DC current or AC sideband detection), or CHIRP before choosing devices. Temperature is OFF, read only, or read/control. DC nanovoltmeter connections can be independent or slave/delta with a Keithley 6220/6221. Position defaults to the OWIS controller's absolute angle. Optionally select the external optical encoder (relative angle) via NI 9361 / Ethernet cDAQ-9183 and enter host/IP and DAQmx channel. Both sources require field-angle calibration; the relative encoder also needs an established reference.

If the external encoder/cDAQ is absent, unconfigured, offline or fails its check, CHECK connections reports a warning and verifies OWIS absolute position instead. A successful motor identity check alone does not satisfy the position check. If motor position also fails, progression remains blocked. The effective source is shown in the device summary and stored as `positionSource` (`owis` or `optical`) in each run. The preferred external selection is retained for a later recheck. The real engine checks position again and aligns a relative optical origin to the referenced OWIS angle before motion; a failure during acquisition aborts instead of silently changing origin.

CHECK connections sits below device configuration and is enabled only after the required instruments and addresses are supplied. Changes to hardware or method invalidate the check; loading a project never restores connection state. The local service checks real hardware; errors identify the missing driver, offline device or mismatched model. Run supports PS10, Keithley 6220/6221 (or Zurich MFLI AC source), and one lock-in (SR830, Ethernet Ametek 7230, or Zurich Instruments MFLI via LabOne) as described in the backend README; it requires calibrated motion conversion and an already initialized/referenced stage. Simulation is explicit and never claims physical devices are online. With temperature OFF, synthetic material behavior uses 295 K internally and saved temperature values are null.

`js/backend.js` implements `window.HHHardware` using the local service. Position requests include `positionSource` and `angleType`: `optical`/`relative` checks the DAQmx chassis, NI 9361 and channel; `owis`/`absolute` uses `?CNT1` through the COM controller. A delta voltmeter request has `parent: 'source'`: only the source interface is opened, then `SOUR:DELT:NVPR?` and serial-forwarded `*IDN?` verify the linked nanovoltmeter. This detects the serial link, not the Trigger Link timing. Connection checks have an eight-second frontend deadline per device and do not enable outputs or motion. The Devices page's TTL reference button polls SR830 Ref In up to the Method timeout (maximum 600 s); it does not start rotation. It configures external rising-edge TTL and requires repeated stable lock observations.

Tests: `node test/run.js`, `node test/modes.js`, `node test/connections.js`, `node test/analysis.js`, `node test/backend.js`, `node test/temperature.js`. Browser regression tests: `node test/browser.js` against a test service on port 18865.
Always-available tabs: History, Log (None/Normal/Verbose/Debug), Project & report (save/load JSON, CSV export, print report).

## Test mode

The app starts with a blank project and no connections. For a synthetic run, select a method, choose Simulation on Devices, configure compatible instruments and addresses, then CHECK connections. Choose temperature control for a sweep, or OFF/read only for measurement and soak steps. New project clears the setup; loaded projects require fresh connection checks.

## Status

- `rust-backend/` implements real connection/readback and acquisition entirely in Rust. It needs installed NI-VISA and, optionally, NI-DAQmx. See its README for supported models and commissioning requirements.
- Real AC-field analysis fits demodulated lock-in voltage/current slopes. Simulation uses synthetic angular envelopes. Both record their acquisition type, sample/method snapshot and simulation flag; partial real runs retain raw data without a fitted result.
- `js/sim.js` and `SimLakeShore` execute synthetic runs, tagged `simulated: true`. The native Rust service is the active hardware backend.
- Fit assumes plateau data after the post-step mask; it does not model lock-in filter dynamics (guide §7, §9.3 `F[...]`).

## Temperature program

Set start/end temperature, a positive step size, ramp rate, heater range, instantaneous |ΔT| limit, mean |ΔT| limit, stability window and timeout, then append the program. Cooling sweeps are automatic when end < start. Only whole increments are generated (up to 1000 points). Each point waits for stability before acquiring data; the step table allows individual overrides.

Here ΔT = measured temperature − target (K). Stability requires the ramp to finish and every reading to remain within the instantaneous limit for a full window. The time-weighted mean absolute error over that rolling window must also pass the mean limit. Any out-of-band reading resets the window. Mean absolute error prevents positive and negative errors cancelling. Existing project steps without a mean limit retain their previous instantaneous-only criterion. Run displays the current error, window mean and time in band.

## Physical properties analysis

Analysis is available without hardware. Open a saved project to recompute each complete run from its raw data and recorded sample/method snapshot. Malformed project structures are rejected before replacing the open project. Partial and fully masked runs retain raw samples and a fit error, with no derived results.

The Analysis tab provides measured/simulated filters, automatic temperature/run-number axes, fit diagnostics, and per-run corrections for thickness (nm), field magnitude (T), tilt (degrees) and independently measured sheet resistance (ohm). Corrections are stored as `analysisSample`, preserving the original `sample` snapshot. Restore acquisition inputs to remove them. Save the project to retain corrections and masks.

Results include signed Hall coefficient, positive sheet and bulk Hall density, Hall mobility and resistivity, with statistical uncertainties where estimable. Invalid/missing values remain blank in CSV and appear as a dash in the interface. Zero Hall slope does not produce infinite density or a carrier assignment. Current-sweep uncertainties propagate within-current fit noise even with only two current levels. Field-lock-in results use the RMS gain documented in `analysis.js` and require calibrated phase.

The raw sample table is a preview of at most 300 samples; raw CSV exports every sample. Mask edits and analysis corrections are recorded in History. Results CSV uses full numeric precision and the selected data-source filter. Reports include the actual analysis inputs for each run, and plots retain runs without temperature by using run number automatically.

## Temperature steps, slow scans and repeat counts

On **Experiment setup**, select **Stabilized steps** or **Slow scan** in the temperature segment builder. Stabilized steps generate a stabilization operation followed by a `measure` operation at every temperature. Each measure operation has a user-defined `repeats` count (1–10000) and `interval_s` wait (0–86400 seconds). Every acquisition is saved separately, with its measurement index, conditions and program-operation snapshot.

A slow scan first stabilizes its starting temperature, then runs a `scan` operation toward the ending temperature. Its rate, endpoint tolerance, timeout and wait are editable in the operation table. Heating and cooling are supported. Scanning requires angular scan, AC-field or CHIRP acquisition; stopped angular steps require a stabilized temperature. Single-current angular scans and AC-field AC-current measurements without background acquisition keep excitation and rotation running between saved acquisition windows when the wait is zero. Multilevel/CHIRP/background methods retain their acquisition sequence. A completed acquisition can extend beyond the time at which temperature crosses the endpoint.

Each run contains per-sample measured temperatures and `temperatureStats` (time-weighted mean, minimum, maximum, start, end and span). The mean integrates adjacent usable samples with trapezoidal weights; excluded intervals are not bridged. If no usable temperature is recorded, the mean is unavailable. Simulation advances temperature during the acquisition instead of freezing it at the initial reading. Analysis and CSV expose the mean/range and mark measurements made during a temperature scan; a fit over an evolving sample is an interval measurement, rather than necessarily the property at one exact temperature.

During a run, edit acquisition conditions and active thermal parameters or change future operations, then click **Apply conditions & program**. Existing traces retain their original method/sample/hardware and operation snapshots. New electrical conditions, repeat counts and scan targets apply between acquisitions. An active stabilization target updates at the next temperature check and resets its stability window. Apply rejects changes to completed operations or the active operation type. Hardware and measurement-principle changes still require Pause and fresh connection checks. Pause retains completed repeats and restarts only an interrupted acquisition.

The minimum supported ramp defaults to 0.1 K/min. For a verified Model 335 with firmware 1.4 or newer, configure 0.001 K/min on Devices. The manufacturer documents that firmware capability in the [Model 335 firmware notes](https://www.lakeshore.com/products/categories/downloads/temperature-products/cryogenic-temperature-controllers/model-335-cryogenic-temperature-controller). The [Model 332 manual](https://www.lakeshore.com/docs/default-source/product-downloads/332_manual.pdf) specifies a 0.1 K/min minimum. Controller limits and the software maximum ramp remain enforced.
## Appearance and built-in Help

Use the **Dark mode** switch at the top right to choose the light or dark workstation theme. It persists in browser storage and synchronizes between the workstation and Help on the same origin. Plot backgrounds, axes, traces, forms, tables and status messages follow the theme; report printing keeps a white background.

**Help** opens `help.html` in a separate tab at the section relevant to the current page. The manual includes startup/access modes, instrument setup, calibration, measurement methods, temperature steps/scans/repeats, live edits, masks, fitting models, physical-property equations, uncertainties, unit conversions, projects, exports and troubleshooting. Native MathML renders its equations without a CDN or network dependency. Search filters the manual, and Print includes every section. `app/docs/chirp-guide.md` packages the full extended CHIRP guide for offline download.

Device section buttons (Magnet, Current source, Measure and Temperature control) remain navigable after local connection and during a verified configuration lock. To edit validated instrument values, release setup or pause the run; this invalidates the old checks and requires re-verification.
