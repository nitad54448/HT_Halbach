# Halbach Hall workstation (app/)

Run `powershell -File rust-backend/start.ps1` from the repository root and open `app/index.html` using Live Server or GitHub Pages. Pair the Devices page with the local Rust service URL and terminal token. See [Rust backend setup](../rust-backend/README.md). Opening `index.html` directly also works for simulation and importing JSON presets; real hardware requires the local service.

Method opens with four cards: DC field, AC field, CHIRP and **Load preset**. Load preset opens a JSON file picker. On Devices, **Save method & devices as JSON** exports the current method and all device settings in the same preset format, excluding sample data and measurements. Loading replaces method/device settings, preserves sample/data, and invalidates connection checks. Examples are in `presets/`: `dc-delta.json`, `ac-dc.json`, and `chirp.json`; edit addresses for your bench. Numerical controls, including TTL timeout, now appear in Experiment setup.

Method defines only the measurement principle: field mode, DC or AC current, and steps or scans. Delta is selected on Devices as source-linked DC voltage acquisition and automatically reverses polarity. AC-field/DC-current measurements acquire each signed current and fit voltage against current with a free intercept. The Data inspect page shows that line. CHIRP specifies cycles per current level and direction, with dwell = cycles / maximum rotation frequency; the universal rotation limit is 1.2 Hz. The guide's slower commissioning speeds remain useful for filter tracking validation.

After successful connection checks, Method and Devices become read only. Use **Stop setup and edit configuration** before starting, or Pause/Abort in Run, to release them. Changing the method principle or devices invalidates the check. Parameter edits in Experiment setup preserve it. During a program, **Apply parameters** validates and queues the settings for the next measurement. Active measurements retain their original settings; each saved run includes its method and device snapshot. Future temperature-step parameters can also be edited and applied; the active/completed steps and sequence structure remain fixed. Real Pause disables outputs and motion, retains partial data and releases hardware sessions; Resume restarts the interrupted step, rechecks identities and restores temperature stability when needed. Device changes require fresh connection checks before Resume.

Workflow: Method → Devices → Sample → Experiment setup → Run → Data inspect → Analysis. Select DC field (steps/scans, DC or AC current), AC field (DC current or AC sideband detection), or CHIRP before choosing devices. Temperature is OFF, read only, or read/control. DC nanovoltmeter connections can be independent or slave/delta with a Keithley 6220/6221. Position defaults to the OWIS controller's absolute angle. Optionally select the external optical encoder (relative angle) via NI 9361 / Ethernet cDAQ-9183 and enter host/IP and DAQmx channel. Both sources require field-angle calibration; the relative encoder also needs an established reference.

If the external encoder/cDAQ is absent, unconfigured, offline or fails its check, CHECK connections reports a warning and verifies OWIS absolute position instead. A successful motor identity check alone does not satisfy the position check. If motor position also fails, progression remains blocked. The effective source is shown in the device summary and stored as `positionSource` (`owis` or `optical`) in each run. The preferred external selection is retained for a later recheck. The real engine checks position again and aligns a relative optical origin to the referenced OWIS angle before motion; a failure during acquisition aborts instead of silently changing origin.

CHECK connections sits below device configuration and is enabled only after the required instruments and addresses are supplied. Changes to hardware or method invalidate the check; loading a project never restores connection state. The local service checks real hardware; errors identify the missing driver, offline device or mismatched model. Run supports PS10/Keithley with one SR830 or Ethernet Ametek 7230 as described in the backend README; it requires calibrated motion conversion and an already initialized/referenced stage. Simulation is explicit and never claims physical devices are online. With temperature OFF, synthetic material behavior uses 295 K internally and saved temperature values are null.

`js/backend.js` implements `window.HHHardware` using the local service. Position requests include `positionSource` and `angleType`: `optical`/`relative` checks the DAQmx chassis, NI 9361 and channel; `owis`/`absolute` uses `?CNT1` through the COM controller. A delta voltmeter request has `parent: 'source'`: only the source interface is opened, then `SOUR:DELT:NVPR?` and serial-forwarded `*IDN?` verify the linked nanovoltmeter. This detects the serial link, not the Trigger Link timing. Connection checks have an eight-second frontend deadline per device and do not enable outputs or motion. The Devices page's TTL reference button polls SR830 Ref In up to the Method timeout (maximum 600 s); it does not start rotation. It configures external rising-edge TTL and requires repeated stable lock observations.

Tests: `node test/run.js`, `node test/modes.js`, `node test/connections.js`.
Always-available tabs: History, Log (None/Normal/Verbose/Debug), Project & report (save/load JSON, CSV export, print report).

## Test mode

The app starts with a blank project and no connections. For a synthetic run, select a method, choose Simulation on Devices, configure compatible instruments and addresses, then CHECK connections. Choose temperature control for a sweep, or OFF/read only for measurement and soak steps. New project clears the setup; loaded projects require fresh connection checks.

## Status

- `rust-backend/` implements real connection/readback and acquisition entirely in Rust. It needs installed NI-VISA and, optionally, NI-DAQmx. See its README for supported models and commissioning requirements.
- Real AC-field analysis fits demodulated lock-in voltage/current slopes. Simulation uses synthetic angular envelopes. Both record their acquisition type, sample/method snapshot and simulation flag; partial real runs retain raw data without a fitted result.
- `js/sim.js` and `SimLakeShore` execute synthetic runs, tagged `simulated: true`. The native Rust service is the active hardware backend.
- Fit assumes plateau data after the post-step mask; it does not model lock-in filter dynamics (guide §7, §9.3 `F[...]`).

## Temperature program

Set start/end temperature, a positive step size, ramp rate, heater range, instantaneous |?T| limit, mean |?T| limit, stability window and timeout, then append the program. Cooling sweeps are automatic when end < start. Only whole increments are generated (up to 1000 points). Each point waits for stability before acquiring data; the step table allows individual overrides.

Here ?T = measured temperature ? target (K). Stability requires the ramp to finish and every reading to remain within the instantaneous limit for a full window. The time-weighted mean absolute error over that rolling window must also pass the mean limit. Any out-of-band reading resets the window. Mean absolute error prevents positive and negative errors cancelling. Existing project steps without a mean limit retain their previous instantaneous-only criterion. Run displays the current error, window mean and time in band.
